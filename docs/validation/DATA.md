# DATA — 日期数据来源与覆盖

本文件记录 CalMon 使用的日期数据：节气静态表、农历来源，以及系统节日/休班的来源识别与覆盖边界。

> 2026-09-15 变更（依据 `docs/UI_REVIEW_FOLLOWUP.md` U2/A3）：**移除内置节假日/调休年度数据（Holidays/CN-YYYY.json）及其加载、回退与说明。** 无系统来源时显示普通公历/农历月历。历史数据只保留在本文档作为记录，不再打包进 App。

## 1. 覆盖范围

- 节气：2025、2026、2027 三个年度，各 24 条（内置静态资源 `CalMon/Resources/SolarTerms/YYYY.json`）。
- 农历：由 Foundation `Calendar(identifier: .chinese)` 计算，覆盖闰月、跨年与时区变化，不使用内置表。
- 节日与休/班：仅来自用户授权的系统日历；App 不内置任何节假日或调休年度数据。

## 2. 节气出处

来源：香港天文台《二十四节气》及对应年度 PDF（文件内 `sourceURL`、`crossCheckURL`），并与紫金山天文台《中国天文年历》口径对照。时区固定 UTC+8，只记录节气日期，不记录具体时刻。

示例核验：2026 年 24 个节气与公开节气表一致（立春 2/4、春分 3/20、清明 4/5、冬至 12/22 等）。

## 3. 系统节日来源

- 授权：系统是唯一真相来源；`refreshAccessState` 每次读取真实授权状态，不在本地记“已授权”。只有状态尚未决定且用户主动点击“获取权限”时才请求。
- 自动识别规则（`HolidayProvider.holidayCalendarCandidate`）：
  1. 日历标题同时含“中国/China/Chinese/PRC”与“节假日/节日/holiday”标记，**且该日历为只读/订阅/immutable**（`type == .subscription` 或 `isImmutable` 或 `!allowsContentModifications`）；或
  2. 只读/订阅、标题含节日标记、且来源标题含“中国/China”。
- 本机实测：命中来源为两个 `中国大陆节假日`（均 `type=3` 订阅、`allowsModifications=false`）；可编辑的个人/工作日历被排除。候选元数据见 `validation/measurements/calendar-source-metadata.txt`。
- 候选与选用：`candidateDetails` 记录所有已发现日历的标题、类型、只读、是否可修改、来源，作为识别证据；`holidayCandidates` 记录命中项。优先保留当前已选来源，否则取第一个命中项。
- 不读取所有个人日程、不默认个人日历、不合并全部事件；不使用私有 API 读 Calendar 数据库。
- 变更通知：`EKEventStoreChanged` 触发 `handleStoreChange`，重新核验授权并重新发现来源（含新增/删除来源），再按当前范围查询，不使用轮询。

## 4. 休/班标记

- 只读取系统事件中**明确**的标记：标题归一化后为 `休/休息/放假/holiday` → 休息，`班/上班/补班/workday` → 补班。
- 不从假期名称推断、不按周末生成；没有系统数据时不保证显示休/班。

## 5. 已知限制与未验证

- 公开 API 只能读取日历标题、类型、只读/订阅、来源标题等元数据。名为“中国节日计划”的个人日历也可能被标题规则命中；这是标题规则无法完全排除的边界，已用只读/来源等交叉条件收紧，但仍不保证 100% 准确。
- 真实首次授权、拒绝/撤销、来源新增/删除后的发现，以及系统实际提供的中国节日日历形态，均需在实机 TCC 环境验证（见 `validation/` 相关报告），本文件不宣称已通过。
- 若系统没有可用节日订阅，则始终显示普通日历并使用节气/农历；不伪装为授权失败。

## 6. 部署行为

- 班/休与节日不再来自任何静态数据；静态资源仅节气。
- 普通日期详情只显示单行摘要（日期+ISO 周、农历年/生肖/月日）与相对日期，不显示“来源未连接/内置兜底/该年度调休安排尚未收录”。
- 权限状态只在设置中呈现。
