# 大日历最终布局：四边等距、事件顶部排列

日期：2026-09-17。状态：已实施（2026-09-17）。**二次修订（本文数值已按此统一）**：用户反馈面板过扁、留白与日历间距不和谐——四边外边距由 24 改为 **50 pt**，窗口内容宽由两栏与边距推导为 **900 pt**，右栏由 528 收窄到 496 并改为**按小日历比例整体放大**（小日历 328 pt 网格 → 右栏 496 pt，网格系数 1.5122），左栏节奏与字号按日期行放大系数 1.2962 同步放大；窗口高度仍按行数驱动，4/5/6 行为 900×537.38 / 565.76 / 638.34。事件容量仍为三条。旧 880 pt 宽／24 pt 边距与旧左栏、右栏数值一律不再使用。

## 1. 优先级与范围

本文是本轮快捷键大日历布局的最新依据，覆盖 UI_COMPACT_ALIGNMENT.md 第 4、5 节及验收中冲突内容，同时覆盖 CALENDAR_PANEL_UI_FOLLOWUP.md、CALENDAR_HOTKEY_PANEL.md 中固定 880×560、固定 11:7、共同内容块垂直居中、事件贴底等旧要求。

搜索、快捷键录入控件、小日历布局、监控、原生材质及业务逻辑不在本轮调整范围。两个日历的单箭头切月、双箭头切年继续保留。

## 2. 最终效果

- 窗口紧贴两栏内容区域，四边外边距一致，不再在上下额外增加大面积留白。
- 左日期标题与右月份标题同基线。左侧日期、时间、星期、农历、分隔线、事件自上而下连续排列。
- 事件区域预留三条容量，内部顶部对齐：一条占第一行，两条占前两行，余量在下面。不能把单条事件放在区域最底部。
- 右侧日期行距均匀，不为了撑满外框拉长日期格或星期与日期之间的间距。
- 月份行数改变时允许窗口基础高度改变；用户拖动时仍整体等比例缩放。不是固定所有月份共用一个窗口宽高比。

## 3. 精确尺寸（s=1）

### 3.1 水平与外边距

| 项目 | 基准尺寸 |
|---|---:|
| 窗口内容宽度 | 900 pt（= 50×2 + 280 + 24 + 496） |
| 上、下、左、右外边距 | 各 50 pt |
| 左栏宽 | 280 pt |
| 栏间距 | 24 pt |
| 右栏宽 | 496 pt（小日历网格 328 pt × 1.5122） |

测量以统一窗口内容坐标为准，不计阴影，不重复叠加透明标题栏 safe area。系统关闭按钮保留，验证它不覆盖标题和交互区域。

四边等距指窗口内容边界到**两栏共同布局区域**的 padding 相等，不要求每一行文字靠近左右边缘，也不要求两栏最后一个可见元素永远同高。事件只有一条时，下方空闲属于三条容量的内部空间，不再扩展为外部留白。

注：下表左栏的加粗项即代码当前字面量（未随字号放大），左栏实际渲染比声明高度短 33.17 pt；该偏差已记录、未修，详见验收记录 `validation/CALENDAR_PANEL_FINAL_LAYOUT_2026-09-17.md`。

事件卡高 51.85 pt、行间距 7.78 pt，三条共 171.09 pt。“全天”与对应卡片垂直居中。卡片一律自然高度，禁止拉长单条卡片填满区域。农历关闭保留既有槽位，避免整栏跳动。

### 3.3 右栏与窗口高度

右栏 = 小日历网格按 496/328 = 1.5122 放大：标题带 48.39、间隔 12.10、星期带 36.29（18.15 pt medium）、间隔 6.05、每个真实日期行 72.59 pt，日期字号 27.21 pt；单元格宽高比与小日历一致（72.59 / 70.86 ≈ 48 / 46.86，近方形）。实际日期行数 n 由现有 model.weeks.count 提供，不新增虚构日期行。

- 右栏自然高度 R = 102.83 + 72.59×n。
- 两栏共同高度 B = max(437.38, R)。两栏均顶部对齐。
- 窗口基础内容高度 H = B + 100。

| 实际日期行数 | 右栏自然高度 | 共同高度 B | 基础窗口内容尺寸 |
|---|---:|---:|---|
| 4 | 393.17 pt | 437.38 pt | 900×537.38 pt |
| 5 | 465.76 pt | 465.76 pt | 900×565.76 pt |
| 6 | 538.34 pt | 538.34 pt | 900×638.34 pt |

4 行月份右栏自然比左栏短 44.21 pt，这部分留在右栏末尾，属于两栏高度差；不能挪到星期与日期之间、拉伸日期行或声称两栏可见底部严格相同。5/6 行月份左栏的剩余空白也留在左栏末尾。优先保证四边共同外边距、均匀日期行距与顶部事件顺序。

取消旧 880×560、旧 880×392 系列与临时建议 880×480 的固定高度。保留横向布局，不用继续缩字来压缩窗口。

## 4. 缩放与切月

- 用户缩放比例 s 仍是一个统一值。当前窗口内容尺寸为 900s × H(n)s，四边距均为 50s；所有内容、图标、间距、事件卡和命中区使用同一比例。
- 当月拖动时，锁定当前 900:H(n) 的内容宽高比，禁止单独横向或纵向拉长。比例随真实拖动实时更新，不能只缩放外框。
- 切月/切年导致 n 改变时，保留 s 和当前窗口顶部中心位置，更新高度及约束；不重新居中整个窗口，不清空选择或快捷键状态，不添加尺寸动画。
- 新尺寸超过当前屏幕可用区域时，优先平移回可用区域；仍放不下时才降低统一 s，禁止裁切或单独压缩高度。系统适配导致的临时缩小不覆盖用户保存的偏好比例。
- 每次重新打开仍按既有规则回到今天、在目标屏幕居中；用当前月份 H(n) 和已保存 s 计算尺寸。旧版保存的缩放比例可以复用，旧固定高度/宽高比不再使用。
- 调整窗口约束不能产生 resize 回调循环；不在每帧写偏好，不重复创建模型、事件提供者、窗口或时钟。

## 5. 事件数量与可访问性

- 三条容量包含“今天/距今天还有…”相对日期行。节日和节日（休）继续分别显示，不合并。
- 0–3 条：普通顶部排列的列表，无滚动行为、无任何滚动条；空状态沿用当前业务规则。
- 超过三条：不删除数据，沿用前份规格的局部滚动兜底，显示区域仍为 171.09 pt、顶部起始，隐藏滚动指示条，支持滚轮/触控板和键盘访问全部项目。
- 超量计数提示放在既有分隔线位置附近，不额外占用三条容量，不使窗口因数量变化增高。禁止通过把普通三条也放进过小滚动区域来复用超量逻辑。
- 不增加事件来源、查询范围、内置节假日或持续后台工作。

## 6. 实施与验收

1. 集中定义上述尺寸，替换旧居中高度公式、贴底事件布局和固定宽高比。不要在旧布局外继续堆叠补偿 padding。
2. 验证 4/5/6 行月份，各搭配 1/2/3 条事件：四边共同外边距 50s；第一条始终位于事件区顶部；三条全部可见；标题同基线。
3. 记录至少一个五行月基准 900×565.76（实测取整 900×566）和放大 1125×707.2（实测 1125×708）的结果；六行月对应 900×638.34（实测 900×639）、1125×797.9。实际连续拖动，检查字体、高亮、命中区和边距同步缩放。
4. 验证五行切六行、六行切四行、跨年和重新打开；宽度/比例按规则保持，高度跟随，窗口不越屏、没有回调循环。
5. 验证超过三条仍可访问所有事件且没有滚动条。分别展示一条和三条截图，不能只凭三条状态推断单条布局正确。
6. 运行相关布局/日期测试及 Release 构建；检查原菜单栏日历、监控、搜索和快捷键注册未回归。证据置于 docs/validation/，未执行项如实标注。
7. 实施后同步 UI_SPEC.md、CALENDAR_HOTKEY_PANEL.md 等旧规格的冲突尺寸及验收规则，旧验收结果不冒充本轮结果。
8. 仅使用构建产物验收，不操作正式安装版本，不自动安装、提交推送、发布 DMG 或触发 Homebrew。
