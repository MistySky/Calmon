# 验收与交付标准

## 1. 交付材料

实施 AI 必须提交以下内容，统一放入 docs/validation/。未完成项目标记“未执行”或“未通过”，不能用截图或文字承诺代替测试。

- REPORT.md：构建版本、环境、逐项结果、剩余问题、限制。
- BUILD.md：从干净检出构建 Debug/Release 的确切步骤、scheme、签名配置、运行方法。
- METRICS.md：最终统计字段/公式、进程归属规则、容量口径、准确性和资源实测。
- DATA.md：中国节假日/班休与节气覆盖年份、官方出处、日期、核验结果。
- screenshots/：同环境真实运行的菜单栏、月历今天/选中节日、监控、设置、右击菜单及必要异常状态小图。
- 测试结果：命令、环境、退出状态和必要摘要；不提交无关庞大日志或用户个人事件数据。

测试环境记录：Mac 型号、芯片、逻辑核心、物理内存、页大小、macOS build、Xcode/Swift/SDK、App build、构建配置、显示倍率及活动监视器刷新间隔。

## 2. 构建与范围

- [ ] 无第三方包或二进制 SDK，无数据库。
- [ ] Debug 和 Release 可构建；Release 脱离调试器运行。
- [ ] 无 Dock 图标、无多余主窗口、无特权 helper。
- [ ] 登录项与需要的隐私声明/授权说明配置正确；不请求无关权限。
- [ ] 全局快捷键使用公开 Carbon/HIToolbox API，不新增辅助功能/输入监控权限；未使用 event tap 或 shell 命令。
- [ ] 正式 AppIcon 显示正常，资源源包未被覆盖。
- [ ] 无历史数据写入、趋势图、个人日程、结束进程或范围外监控。
- [ ] docs/、原型图、验收日志未进入 App bundle。

## 3. 交互与生命周期

- [ ] CPU/MEM 和日期是两个独立状态栏项目。
- [ ] 分别左击打开对应面板，不能共同打开月历。
- [ ] 右击任一项目只出现“偏好设置…”和“退出”，不误触左击。
- [ ] 同时最多一个弹窗；再次点击/外部点击/Esc 关闭。
- [ ] 设置窗口不会因打开其他弹窗重复创建。
- [ ] 模块四种开关组合正确，全部关闭仍可恢复设置与退出。
- [ ] 关闭监控不再查询；重新开启没有重复定时器。
- [ ] 休眠不保活、唤醒重建基线，不补跑积压周期。
- [ ] 所有操作有键盘与辅助功能路径。

- [ ] 录入合法组合后可从至少两个其他应用前台唤出；再次触发、Esc、外部点击、Cmd-Tab 关闭。
- [ ] 裸字母、仅修饰键、纯 Option/Shift、Caps Lock/Fn/媒体键被拒绝；系统常用组合给出原因。
- [ ] 改绑先尝试新组合，注册失败保留旧组合并给出原因；相同组合视为无变更成功。
- [ ] 清除按钮取消注册并移除保存值；重启后按设置恢复。
- [ ] 初次内容区恒为 1013.70×580（固定 6 行网格），拖动四边/四角保持 1013.70:580；1×/1.25× 字体、日期格、卡片、按钮在拖动过程中持续同步缩放。
- [ ] 两栏顶部对齐、四边外边距 50 pt 相等；左右日期/月标题共享同一标题带基线（≤1 物理像素差）；底部无独立“今天”按钮，事件中的“今天”、T 键与重新打开回今天保留。
- [ ] 设置“日历快捷键”为单个右对齐原生录入框（104×24 pt），× 在框内；未设置/录制中/已设置/长组合/冲突各态右边界不移动，组合在清除区外居中，错误说明位于控件下方。
- [ ] 四边外边距均为 50；右栏布局区 609.70，560 pt 月历网格水平居中；日期格 80×64、日期字号 24、农历 16，列与行无弹性间隔。

- [ ] 监控三卡副行为两行且左对齐（已使用 / 未使用），两行与圆环主数值来自同一快照；CPU 两行恒加 100%，内存/磁盘两行相加为总量；不可读时显示 --，不显示假 0；圆环与副行之间保留额外间距。
- [ ] 左栏按 44→12→16→4→60→12→24→20→8→24→20→1→16→160 的固定流程排列；事件区顶部 261，分隔线位置不随事件数量移动。
- [ ] 事件卡 48、间距 8、三卡区 160，顶部排列；≤3 条无滚动条，>3 条用同高局部滚动区访问全部事件。
- [ ] 拖动锁定 1013.70:580 并实时同步缩放；切月/切年不改变窗口尺寸与位置；超出屏幕先平移、仍放不下才临时降低 s。
- [ ] 事件数量与月份行数都不改变窗口尺寸；多事件仅在左栏滚动；T 键与重新打开回到今天。
- [ ] 拖动结束后再次打开恢复比例；每次打开选中今天、显示当前月；日期状态不恢复。
- [ ] 唤出位于鼠标所在屏幕 visibleFrame 居中，边界距可用区至少 24 pt；拖到更小屏幕或拔屏后等比收回可见范围。
- [ ] 打开面板关闭两个弹窗；打开弹窗/设置关闭面板；关闭日历关闭面板并取消注册，重开恢复。
- [ ] 进入休眠关闭、唤醒不自动弹出；退出 App 前注销快捷键。
- [ ] 时钟仅面板可见时每秒刷新，关闭后无新增回调；与菜单栏日期、监控调度互不影响。
- [ ] 新旧日历查看同一天时日期、农历、周起始、ISO 周数、事件与班/休一致；不触发两份范围查询。
- [ ] 面板可见、监控关闭、Release 构建、目标硬件预热后 5 分钟：平均进程 CPU ≤ 2%，physical footprint ≤ 220 MiB；50 次开关后静置 60 秒增长 ≤ 10 MiB。
- [ ] 菜单栏月历与快捷键面板都可用双箭头按年翻阅（±12 个月单次调用），闰日按月末截断（2028-02-29 → 2029-02-28）；选中日、农历、ISO 周、事件同步更新。

## 4. 日历正确性

- [ ] 4/5/6 行月份、周一/周日起始、跨年、闰年与农历闰月正确。
- [ ] 邻月点击切月，重新打开回今天，今天按钮与选中状态正确。
- [ ] 节日优先显示，长名称可读，农历开关不隐藏休/班标记。
- [ ] 日期详情单行摘要（日期+ISO 周、农历年/生肖/月日）与自然日差正确。
- [ ] 时间跳变、时区切换、夏令时、跨午夜和唤醒后无错日。
- [ ] 多日全天事件按正确日期范围显示，多来源节日去重。
- [ ] 系统事件明确标记的休/班正确显示；无系统数据时不猜测，不按周末或节日名称补造。
- [ ] 不内置节假日/调休数据；无授权、无来源或无内容时显示普通公历/农历月历，节气表有来源与覆盖范围。
- [ ] 无数据不显示“来源未连接/内置兜底”大段提示，权限状态集中在设置。
- [ ] 未授权、拒绝、日历/来源删除、来源变更、无事件分别正确显示，授权有效不重复请求。
- [ ] 快速切月不出现旧月结果覆盖、重复查询或无限缓存。

## 5. 监控准确性

### 5.1 对照方法

- 预热 60 秒，观察空闲、稳定中等负载、稳定高负载；各稳定场景至少 60 秒。
- 内存对照覆盖应用占用增长、释放后文件缓存、发生压缩等状态。测试不得使用户系统进入失控压力。
- CPU 比较活动监视器底部 System + User；固定 3 秒采样与其时间窗不一定一致，使用稳定平台与较长窗口均值，不能仅凭同屏一帧判断。
- 内存对照 Memory Used 和 Physical Memory 的原始量及百分比；注意系统显示单位和舍入。
- 应用对照同一 PID 集合和已验证字段，不以主进程单行对照应用组。
- 磁盘对照同卷同 API 字段，验证 APFS 共享容量不会被累加，不要求混合可回收空间的其他 UI 数字完全相等。
- 保存临时验证时间戳和原始字段，验证结束后 App 不继续自动记录。

### 5.2 通过条件

- [ ] CPU 确定性样本计算精确，处理空闲/全忙/混合/零增量/回绕/失败恢复。
- [ ] 稳定 CPU 60 秒窗口均值与活动监视器同口径偏差 ≤ 2 个百分点，且无持续偏移。
- [ ] 稳定内存场景未取整占比偏差 ≤ 1 个百分点；文件缓存/压缩变化不引入持续系统性偏差。
- [ ] 内存完整字段映射有证据；不能用误差阈值掩盖错误公式。
- [ ] 应用归属 PID 无重复、无跨应用误合并；单 PID 数值与其系统来源一致，组结果与已读 PID 汇总一致。
- [ ] 部分不可读状态明确，不把失败设零；目标应用覆盖清单包含浏览器多进程、系统 App、普通单进程 App。
- [ ] 菜单栏/圆环/文字同源，无 24/32 GB 却显示 67% 等矛盾。
- [ ] 已用、总量、剩余及各分项在原始字节层面一致；舍入差异有说明。
- [ ] 磁盘总量/可用/百分比同卷同口径，256/512 对应 50%。
- [ ] 读取失败不保留旧值伪装实时；时间窗差异不能成为长期误差的理由。

任何一个统计口径未证明，相关功能不能标记验收通过。测试阈值是工程检查门槛，不是允许错误公式的许可。

## 6. CalMon 自身性能

所有预算用于 Release、无调试器、正常静止桌面的目标硬件实测。活动监视器的单进程 CPU 口径通常以一个逻辑核心为 100%，此处不得与整机归一化百分比混用。测量工具的扰动需在报告注明。

### 6.1 首版工程预算

| 场景 | CPU / 内存 / 唤醒要求 |
|---|---|
| 监控开、弹窗全关 | 预热后 10 分钟平均进程 CPU ≤ 0.5%；physical footprint ≤ 120 MiB |
| 监控面板开、显示前八行 | 5 分钟平均进程 CPU ≤ 2%；physical footprint ≤ 220 MiB |
| 监控关、弹窗全关 | 无 App 自建周期监控回调；不能声称系统框架绝无唤醒 |
| 监控开、弹窗关 | 只存在一个 3 秒监控调度源，App 自建监控调度平均 ≤ 0.4 次/秒 |
| 50 次开关两个弹窗和设置 | 预热后占用不持续线性增长；静置 60 秒后 footprint 相对循环前增加 ≤ 10 MiB |

以上是工程验收预算，不是已测成绩。超出必须定位、优化并复测；不能直接修改上限使其通过。设备环境确实使预算不适用时，提交证据供独立验收评审。

### 6.2 测量场景

- [ ] 空闲仅菜单栏 10 分钟；记录 CPU 均值、峰值、physical footprint 和 idle wakeups。
- [ ] 监控面板静止 5 分钟；记录逐应用查询耗时和采样次数。
- [ ] 监控关闭 10 分钟；检查没有统计调用和多余调度源。
- [ ] 月历静止 2 分钟；无持续布局、日历轮询或自定义动画。
- [ ] 快捷键面板可见、监控关闭 5 分钟；记录 CPU 均值、physical footprint、时钟回调次数与总唤醒差值。
- [ ] 快捷键面板开/关各 50 次；关闭后新增时钟回调为 0，静置 60 秒 footprint 增长 ≤ 10 MiB。
- [ ] 面板 1×/1.25×/1.5× 拖动缩放各若干次；观察者、任务、注册与日期查询数量不增长。
- [ ] 两个弹窗和设置各开关 50 次；检查计时器、观察者、任务、图标缓存和内存趋势。
- [ ] 连续切换 24 个月；查询范围有限，旧数据可回收。
- [ ] 反复登录项切换、监控切换及睡眠唤醒；无重复采样。
- [ ] 原始数据查询离开主线程，交互期间无明显卡顿或任务队列积压。
- [ ] 图表仅随新快照重绘，无高频动画或单独刷新循环。

总 idle wakeups 和能耗需报告，但不把它们与 App 自建定时器触发次数等同。观察差异时用 Instruments 定位，不用猜测解释。

## 7. UI 验收

- [ ] 按 UI_SPEC.md 使用同一字体、层级、边距、圆角层级和语义颜色。
- [ ] 月历/监控使用同一外壳策略，设置单页表单，右击原生菜单。
- [ ] 文字不裁切，正文可读，无重复投影、粗白框或多重玻璃层。
- [ ] 100%/--% 不跳宽，长应用名/节日名/来源名不破坏对齐。
- [ ] 今天/其他选中日期、休/班、加载/失败/禁用可区分。
- [ ] 应用列表悬停/滚动/键盘操作时不跳行，焦点保留在同一应用。
- [ ] 监控搜索默认收起为 24 pt 圆形入口；展开只向左、可见边框左右边缘与占用条轨道对齐、不越过轨道左边缘；展开态有焦点/有查询时不显示放大镜，文字左内边距 6 pt、清除命中 20 pt 且不遮挡文字或候选输入；长中文在框内水平滚动；空查询失焦收起、有查询失焦保持、清空保持展开。
- [ ] 浅色、深色、减少透明度、增加对比度、不同屏幕倍率均检查。
- [ ] 小屏幕边缘不越界、可滚动区域不吞掉必要操作。
- [ ] 快捷键面板与已有两弹窗在同屏、同背景、同外观、同活动态下对照材质；差异如实记录。
- [ ] 初次大小、1.25×/1.5× 放大、选中日期与多事件、快捷键设置状态均有组件截图。
- [ ] 同环境分别截取组件小图；截图中的数值来自真实运行，不伪造图形。

## 8. 独立验收结论格式

REPORT.md 最终用三类状态列出每项：通过 / 未通过 / 未执行。

结论必须包含：
- 实际构建和运行的平台；
- 已通过功能与准确性结果；
- CPU、内存、唤醒和内存循环测试的原始测量摘要；
- 数据年份、应用进程覆盖边界及权限限制；
- 所有未通过/未执行事项及复现步骤。

只有全部必需项通过，才能声明交付完成。文档齐全、能打开窗口或截图好看均不能单独证明完成。
