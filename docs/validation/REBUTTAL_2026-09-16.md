## S1 · 主张：监控面板顶部设备行比下方卡片更宽（左超出、右偏短）

**核实结论：在当前构建不成立（已修复）。** 附件截图为**旧布局**（仍显示“10 核”且顶部无外框），与当前构建不一致。

方法与证据（逐行像素边界检测，“背景→卡片”跳变；原始记录见 `measurements/rebuttal-toprow-edges.txt`）：

| 行（归一化 y） | 内容 | 卡片外框左右边界 |
|---|---|---|
| 0.05 / 0.07 / 0.09 | 顶部设备行外框 | 0.032/0.033 .. 0.968 |
| 0.15 | 设备行下方间隔 | —（该行无卡片，边界来自相邻卡） |
| 0.20 | CPU/内存/磁盘三卡外框（含内部圆环跳变） | 0.032 .. 0.968 |
| 0.80 | 应用列表卡外框（含图标/条内部跳变） | 0.032 .. 0.968 |

三者外框左右边界一致（0.032/0.033 .. 0.968；y=0.05 因抗锯齿取到 0.033，差 0.001 属取整），因此不再有“前面超出、后面短一截”。原始 `y=0.20`、`y=0.80` 行还包含圆环/图标条形等内部跳变点，不是外框边界，已在表内注明。

旧现象的成因与现状：
- 旧版设备行是**无外框、左对齐并整体缩放**的裸文字，会顶到内容左缘、右侧留空，视觉上比卡片宽。
- 现版已改为：与下方卡片**同一 `UIStyle` 外框**（`cardBackground`/`cardCorner`/`cardPadding`），内容居中、项间等距（14 pt），左右边界与卡片一致。
- 当前内容：`Apple M1 Pro　macOS 27.0　32 GB　494.4 GB　已运行 1 天`（已移除“10 核”）。

复现：启动最新 Release → 左击 CPU/MEM → 截图 → 见 `screenshots/02-monitoring.png`。
