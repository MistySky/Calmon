# 菜单栏日期字号调整规格

## 1. 目标与范围

依据用户提供的同屏对比图：左侧为 CalMon，右侧为参考日历。将 CalMon **菜单栏日期文字**适度放大，使其视觉大小接近右侧参考。

本次只调整菜单栏日期，不调整 CPU/MEM 字体、监控弹窗、月历弹窗、设置界面或业务逻辑。不新增字号设置项。

本文优先于 UI_REVIEW_FOLLOWUP.md 中“保持现有字号”的约束，但仅覆盖菜单栏日期这一项。其他既有约束继续有效。本文为实施规格，不代表代码已修改或实机验收通过。

## 2. 当前实现与确定方案

当前源码：`CalMon/App/UIStyle.swift` 的 `Fonts.menuBarDate` 使用系统字体 **13 pt / regular / 等宽数字**；`Fonts.menuBarMetric` 使用等宽数字系统字体 **8.5 pt / medium**。日期由 `MenuBarController.dateImage(_:)` 按字体实际尺寸绘制。

| 项目 | 实施要求 |
|---|---|
| 日期字号 | 从 12 pt 改为 **13 pt**（依据源码字号依据，取代此前基于截图的 12 pt 估计） |
| 日期字重 | 保持 **regular**，先通过字号匹配，不同时加粗 |
| 字体 | 系统**等宽数字**字体 `monospacedDigitSystemFont`，不指定第三方字体 |
| 日期格式 | 保持现有格式，例如 `9月16日 周三`；星期开关继续有效 |
| 水平布局 | 按完整字符串自然宽度计算；日期绘图左右 padding 保持 0，不增加额外空格或字距 |
| 垂直布局 | 保持菜单栏内垂直居中；绘图高度随字体测量，无裁切 |
| CPU/MEM | 严格保持现有 8.5 pt / medium、两行布局、列宽算法与间距 |
| 交互 | 保持两个独立 NSStatusItem、独立左击弹窗、现有右击菜单 |

**13 pt / 等宽数字为有源码依据的目标值。** 不再以截图估计值 12 pt 为准；不得自行持续放大、改为粗体或连带调整监控。

## 3. 实施边界

1. 首选只修改 `UIStyle.Fonts.menuBarDate`，保留所有其他字体常量。
2. `dateImage(_:)` 已按字体测量宽高，先沿用现有算法；只有实测出现裁切或垂直偏移时，才调整日期专属画布，不修改 `metricImage(cpu:mem:)`。
3. 字号增大导致日期项目自然变宽属于预期结果。不得为追求相同宽度压缩字形、缩放整张图、裁切日期或修改系统项目间距。
4. 保持 template image 的系统着色，不硬编码白色或黑色显示效果。
5. 不更改刷新频率、计时器、采样、授权、图标或打包安装逻辑，不自动安装或替换用户 App。
6. 完成后将 UI_SPEC.md 的菜单栏日期条目同步为实际字号与现有 0 padding，并链接本文；不因旧规格中的其他字号或 padding 数值恢复旧监控布局。

## 4. 验收

- 在同一显示器、相同缩放和菜单栏高度下，将 CalMon 日期与用户参考日历并排截图；对比相同日期字符串，避免用不同内容宽度判断字号。
- 日期视觉大小接近右侧参考，字形清晰，月份、日期、星期均不截断，上下无贴边。
- 检查短日期、双位月日（如 `11月28日 周六`）及关闭星期；均按内容自然宽度展示。
- CPU/MEM 的字号、字重、两行间距和列布局与修改前一致；不以日期变化为由调整监控。
- 日期左击仍打开月历，监控左击仍打开监控；右击行为保持。
- 本次为低影响字体调整，无需新增镜像式单测。完成 Release 构建检查和同屏视觉验收即可；未执行项如实标记。
- 提交菜单栏局部前后截图、最终字号和必要的日期画布调整说明。仅保存组件验收图，不新增整套原型图库。

## 5. 交付结论格式

明确报告：日期字号 `12 → 13 pt`、字体等宽数字、字重 regular、监控字体未改、是否通过同屏视觉检查，以及是否产生裁切或交互回归。不要把“代码已修改”直接写成“视觉已验收”。
