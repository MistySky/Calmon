# 监控应用名称搜索实施规格

## 1. 目标与优先级

将监控弹窗应用列表标题栏右侧的“按内存降序”文字替换为紧凑的原生搜索框，按聚合后的应用显示名称筛选列表。

本文是用户已确认的本轮需求，覆盖旧文档中“按内存降序”文字及搜索状态下列表展开方式的冲突条目。排序规则仍为内存降序；其他现有功能、视觉与性能约束继续有效。

**2026-09-17 二次更新（UI_COMPACT_ALIGNMENT.md §2）**：展开态不再使用带内置放大镜的 `NSSearchField`，改为原生紧凑组合（`NSTextField` roundedBezel/small + 框内清除按钮），有焦点/有查询时不显示放大镜；文字左内边距 6 pt、清除命中 20 pt、尾端内边距 2 pt；可见边框左右边缘对齐占用条轨道，宽 64 pt 不变。

**2026-09-17 更新（SEARCH_AND_YEAR_NAVIGATION.md §2，优先于下文冲突条目）**：标题行右侧默认是 24 pt 圆形放大镜入口，点击后才向左展开为原生搜索框；展开宽度上限为 `applicationBarWidth`（当前 64 pt），右边缘与下方占用条右边缘对齐，左边缘不得越过占用条左边缘；标题行高度固定 24 pt。下文的 130 pt 宽度与“常驻搜索框”描述作废，其余匹配规则、生命周期与筛选行为继续有效。

## 2. 界面

- 左侧保留“应用内存占用”，右侧替换为搜索框，置于同一标题行。
- 使用 macOS 原生搜索控件，带放大镜和原生清除按钮；占位文字“搜索应用”。优先采用局部原生搜索字段，必要时用轻量 NSSearchField 包装，避免 searchable 将控件移到窗口其他位置。
- 搜索框宽度改由 `UIStyle.Metrics.applicationBarWidth` 推导（展开态为其值减去原生边框留量），采用原生 small 控件尺寸，与左侧标题垂直居中；不再使用独立的 130 pt 常量。
- 保持现有面板宽度、卡片背景、边距、标题及应用行字体；不要为搜索框改大弹窗或缩小已有文字。
- 有文本时可清除；辅助功能名称：收起态圆形入口为“搜索应用名称”，展开态输入框为“搜索应用名称”，占位“搜索”。不能只依赖图标表达用途。
- 删除“按内存降序”可见文案，不增加排序切换按钮或其他过滤选项。

## 3. 名称匹配规则

1. 仅匹配已聚合应用行的显示名称，即 AppUsage.name。不要检索 bundle ID、进程名、路径、PID 或隐藏的 helper 名称。
2. 模糊检索在本需求中特指**连续子串匹配**，不要求完整应用名；不实现拼音、首字母、错字纠正或任意字符跳跃匹配。
3. 忽略英文大小写，去除查询首尾空白；内部空格保留原意。空字符串或全空白视为无查询。
4. 中文按实际名称匹配：输入“飞”或“飞书”均匹配“飞书”，输入“feishu”不匹配“飞书”。
5. 输入“chat”匹配“ChatGPT”和“ChatGPT Classic”；只匹配名称包含该子串的应用。

## 4. 数据、排序与展示

- 搜索范围为当前完整的已识别、聚合后的应用快照，不限默认前八行，也不限搜索前是否点击过“查看更多”。
- 飞书及其已归属 helper 仍聚合为一行，不因查询拆分，不改变占用计算与进程归属。
- 输入后即时在本地筛选；不等待下一次三秒采样才响应。
- 活跃查询时显示全部匹配结果，超过现有列表高度后滚动；隐藏“查看更多/收起”按钮，不把搜索模式写入原有展开状态。
- 清空查询恢复原有展开/收起状态及其展示规则，不要求恢复此前精确滚动位置。
- 保持内存降序和既有平局排序。继承用户操作列表时冻结顺序的规则；新查询立即更新匹配集合，不能因旧 frozenIDs 把不匹配行带回来。
- 每次有效监控快照更新后重新筛选，数值继续实时刷新；应用启动/退出随现有采样结果进入或离开列表。
- 有有效查询、采样成功但匹配为空时，列表区显示“未找到匹配应用”。
- 首次采样未完成时继续显示“正在读取…”；读取失败沿用现有失败/部分数据表达，不把数据不可用误报成搜索无结果。

## 5. 输入与生命周期

- 打开监控弹窗时搜索为空，不自动抢占输入焦点；可通过点击或 Tab 进入搜索框。
- 支持原生中文输入法，不能在组合输入期间强制替换文本、跳焦点或关闭弹窗。
- Esc：输入法候选或组合输入优先交由系统处理；正常编辑时若有查询，第一次 Esc 清空查询并保持弹窗，查询为空时 Esc 关闭弹窗。输入法优先处理属于原生输入交互，不以一次 Esc 必须关窗为由破坏中文输入。
- 点击清除按钮不关闭弹窗；点击其他 App、再次点击监控菜单栏或切换到日历，仍按既有行为关闭监控弹窗。
- 监控弹窗真正关闭后清空搜索词；重新打开不得保留旧查询。注意现有 hosting controller 会复用，不要仅依赖 View 的首次初始化重置。
- 关闭弹窗仍停止逐应用采样并清理既有缓存，不为搜索保留后台查询任务。

## 6. 实施边界与性能

- 仅使用现有内存快照筛选应用名称，不增加进程枚举、图标读取、磁盘读取、轮询或定时器。
- 无搜索历史、无持久化、无第三方依赖、无数据库、无网络请求；轻量本地过滤不引入异步搜索服务或额外状态层。
- 搜索词属于监控界面临时状态，不放入共享 Preferences，不影响日历模块。
- 首选修改 MonitoringView，必要时加入同文件轻量原生控件包装、UIStyle 尺寸常量，以及最小的弹窗关闭重置接线。不得借机重构采样器或调整统计口径。
- 不改菜单栏日期字体、CPU/MEM 字体、设备信息行、三个圆环、月历、设置或右击菜单。
- 不实现结束进程、排序选择、拼音搜索、历史记录、全局快捷键或额外动画。
- 不自动安装、替换、退出用户正式 App，不发布 GitHub、不触发 Homebrew；本次交付代码与验证结果，发布另行授权。

## 7. 验收清单

### 名称与数据

- “飞”命中“飞书”；“feishu”不命中仅名为“飞书”的应用。
- “chat”“CHAT”均命中“ChatGPT”和“ChatGPT Classic”。
- “  飞  ”等价于“飞”；空白查询恢复普通列表。
- 仅存在于 helper 进程名中的字符串不单独产生应用行。
- 未展开时，也可搜到原列表第九行及之后的应用。
- 保持原聚合数值、内存降序规则和部分不可读状态。
- 无匹配、加载中、读取失败三种状态区分正确。

### 交互

- 查询有结果时，数值随既有三秒采样刷新，无额外采样。
- 超过八个匹配结果可滚动查看，搜索期间没有“查看更多/收起”；清空后恢复搜索前展开状态。
- 中文输入法可正常输入“飞”；候选选择和取消不误关弹窗。
- Tab 可聚焦，清除按钮有效，Esc 按第 5 节处理；焦点不因采样刷新丢失。
- 外部点击关闭、切到日历后再打开、再次点击监控菜单栏关闭后再打开，搜索均为空。
- 搜索框不遮挡标题，不改变其他组件字体与布局。

### 测试与交付

- 为中文部分匹配、英文大小写、空白、不匹配拼音及搜索覆盖完整列表提供有意义的测试；避免为固定字号或控件属性编写镜像式测试。
- 运行受影响测试和 Release 构建；实际验证中文输入、Esc、关闭重开与刷新焦点。做不到的交互明确标为未执行，不用静态代码检查替代实测。
- 验收证据放 docs/validation/：简明结果、默认/有匹配/无匹配的组件截图。截图来自真实运行；如用测试数据验证第九行场景，明确标为测试夹具。
- 同步 UI_SPEC.md 的列表标题行和搜索交互、MONITORING.md 的列表展示条目，链接本文；不改统计公式、性能预算或旧验收证据。

验收结论明确区分已通过、未通过和未执行，并说明应用代码改动范围；未完成真实交互验证时不宣称全部验收通过。
