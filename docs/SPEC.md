# 产品与技术规格

## 1. 平台与范围

- 平台：macOS 27，优先 Apple silicon；使用支持目标系统的稳定 Xcode、Swift 与 SDK。不得声称未实测的硬件受到验证。
- 技术：SwiftUI 内容视图、AppKit 系统集成、Foundation 日期与格式化、EventKit 节日日历、ServiceManagement 登录项、公开 Mach/libproc 系统统计。
- 零第三方依赖，无数据库，无监控历史，无远程服务、账号或遥测。
- 无 Dock 图标，不显示普通主窗口；仅菜单栏、按需弹窗与设置窗口。
- 允许当前值圆环和占用条；禁止历史趋势图和持续动画。
- 不做个人日程、事件编辑、提醒、结束进程、温度、GPU、网络或磁盘读写速率。
- 优先低 CPU/内存占用，但不能以牺牲数据准确性达成低占用。

## 2. 菜单栏与点击

### 2.1 两个独立项目

- 监控项目：CPU 与 MEM 上下两行，数值在标签右侧，整数百分比；CPU 在上、MEM 在下。
- 日历项目：格式“9月15日 周二”，星期可关闭；无年份、时分秒或前导零。
- 默认监控在左、日期在右；各自独立命中与系统高亮，无跨两个项目的背景或分隔线。
- 监控左击切换监控弹窗；日期左击切换月历；右击任何一项只打开原生菜单。
- 右击菜单：“偏好设置…”、分隔线、“退出”。不增加“系统日历”或其他菜单项。
- 同时最多一个弹窗。打开另一面板先关闭当前面板；点击外部、Esc 或再次点击本项目关闭。
- 设置和退出作用于整个 App；弹窗内无设置、退出按钮。
- 提供原生键盘/辅助功能菜单路径；不要只靠鼠标右击才能让辅助技术访问设置。
- 两个项目均关闭时保留一个静态小型入口；其点击/右击均提供设置与退出，不采样。
- 日期跨天、时区变化、系统时间变化和唤醒后正确更新。

### 2.2 开关矩阵

| 日历 | 监控 | 行为 |
|---|---|---|
| 开 | 开 | 两个独立项目及独立弹窗 |
| 开 | 关 | 仅日期；停止全部监控查询 |
| 关 | 开 | 仅监控；取消不需要的日历读取 |
| 关 | 关 | 仅保留管理入口；无监控调度 |

禁用模块会关闭其弹窗，但保留偏好值。再次启用监控重建 CPU 基线。

## 3. 月历

- 月标题、上/下月按钮、回到今天按钮；7 列、按实际月份显示 4–6 行，无日期格边框。
- 默认周一起始，可改周日；周数固定采用 ISO 规则，不随排列设置改变。
- 日期格显示公历和农历；节日 > 节气 > 农历日名作为第二行优先级。完整信息在选中详情中展示。
- 今天实心红圆，其他选中日期浅红圆。今天同时被选中时仍保持实心红圆。
- 红色“休”、灰色“班”角标；提示点只代表节日/节气详情，不代表个人日程或自动认定休假。
- 邻月日期淡化；点击邻月日期切到对应月份并选中。
- 每次重新打开回到当前月份并选中今天。“今天”按钮同样重置。
- 详情包含公历、星期、ISO 周数、农历年/生肖/月日、距今天的自然日差。
- 今天显示“今天”；未来“距今天还有 N 天”；过去“距今天已过 N 天”。不能用秒差除 86400。
- 同一天同一节日多来源去重，只保留一份节日名称及明确的休息/补班信息；不同节日不能误合并。
- 空状态文字为“当天无节日”；无权限、超出数据范围与真实无节日必须区分。
- 只显示节日信息，不显示“暂无日程”或暗示读取个人日程。
- 详情较多时局部滚动；极小可用屏幕允许整个内容滚动，不裁切操作区域。
- 键盘支持日期移动、切月、回到今天和关闭；为日期、高亮与班/休提供明确辅助功能标签。

## 4. 节日、农历与调休

### 4.1 数据来源职责

- 农历使用 Foundation 中国历；覆盖闰月、跨年和系统时区变化。
- 节日与休/班只从系统节日日历通过 EventKit 读取；查询仅限自动识别的来源和可见日期范围。**不内置节假日或调休年度数据。**
- 没有可用系统来源时显示普通公历/农历月历，不猜测、不按周末或节日名称生成休/班。
- 节气由有出处、可测试的年度静态表（SolarTerms/YYYY.json）提供并标明覆盖范围；不能认为农历 API 自动提供二十四节气。
- 静态资源是版本化产品数据，不属于监控历史或数据库。
- 官方日期按中国标准时间的公历日期记录；界面按用户本地日期显示并匹配同名日历日期，不把日期字符串当 UTC 时间戳转换导致错日。

### 4.2 优先级与失败

- 休/班只来自系统事件中明确的标记，不从假期名称或周末推断；没有系统数据时不保证显示休/班。
- 无授权、无来源或无内容时显示基础公历与农历月历，不使用“来源未连接/内置兜底”大段提示；权限状态集中在设置。
- 仅在用户主动点击设置中的“获取权限”时请求授权；不在启动、打开月历或切月时请求。
- 拒绝、限制、来源丢失和读取失败分别呈现短状态与设置入口；授权有效时持续复用，不重复请求。
- 系统授权是完整日历访问，但 App 不修改事件、只读取自动识别的中国节日日历，不读取全部个人日程。
- 全日事件按半开区间处理；多日节日逐日落位，归一化名称去重。
- 可见范围包含邻月格子；只缓存当前范围，切月替换。监听系统日历变化（含来源新增或删除）重新发现来源，避免 3 秒轮询。
- 快速切月取消旧任务或用版本号丢弃旧结果，避免过期结果覆盖当前月份。

## 5. 监控弹窗

从上到下：

1. 静态设备概况：芯片名称、macOS 版本；不要重复一份独立更新的内存/磁盘数字。
2. 三个当前占用卡片：CPU、内存、磁盘，各有圆环和百分比；内存/磁盘下方显示已用/总量。
3. 应用内存列表：应用图标、名称、内存 MB/GB、占物理内存比例条；固定按内存降序。
4. 默认显示前 8 个应用，“查看更多…”在同一面板内展开完整可滚动列表，可“收起”；不打开新窗口。
5. 应用按软件聚合：主 App 及其可证明归属的 helper 合并为一行（如飞书与 Lark Helper），数值为组内已读 footprint 合计。

规则：

- 仅当前值，无坐标轴、时间范围或历史记录。
- 圆环、条形、概况、菜单栏来自同一有效快照；不能同时出现 24/32 GB 与 67%。
- 不展示内存组成（应用/联动/压缩/剩余）卡片或组成条。
- 每个应用占用条分母为物理内存，不按列表最大值缩放；含文字数值，不能只用颜色表达。
- 稳定排序：降序，数值相同按名称及稳定 ID；用户悬停/滚动/键盘操作列表时暂缓重排，数值继续更新，离开列表或结束操作后重排。
- 进程退出、应用启动、权限受限和部分可读情况按 MONITORING.md 处理。
- 无数据时显示“正在读取…”；读取失败显示短原因或“不可读取”，不能显示伪造零值。
- 面板打开时读取逐应用与磁盘数据；关闭立即停止逐应用查询，释放列表的临时采样缓冲，不无限缓存图标。
- 应用图标从系统读取并按展示尺寸缓存，键为应用稳定标识；应用退出后回收不再需要的缓存。

## 6. 设置

原生单页分组表单，无侧栏、标语、大图标或大块宣传内容。

| 组 | 设置 | 默认与行为 |
|---|---|---|
| 通用 | 登录时启动 | 关；以系统登录项真实状态为准 |
| 菜单栏 | 日历 | 开；日期项目和月历 |
| 菜单栏 | 监控 | 开；监控项目与采样 |
| 日历 | 显示星期 | 开；菜单栏日期 |
| 日历 | 显示农历 | 开；关闭格子/详情农历，节日与班/休不受影响 |
| 日历 | 中国节假日 | 开；控制中国节日及班/休展示 |
| 日历 | 每周开始于 | 星期一；可选星期日 |
| 日历 | 系统日历权限 | 显示真实授权状态；未决定时可“获取权限”，拒绝/受限显示状态与系统设置入口；不手选来源 |

- CPU/内存固定每 3 秒刷新，显示为说明，不提供刷新频率下拉框。
- 偏好立即生效并通过 UserDefaults 持久化；无保存/取消按钮。
- 关闭日历后，其子设置禁用但保留值。
- 登录项使用 SMAppService.mainApp；处理需批准、注册失败和用户从系统设置移除，不假定本地布尔值等于系统状态。
- 无主题/字体设置；遵循系统明暗、强调色、对比度和减少透明度。

## 7. 项目结构与边界

一个 Xcode 工程，一个 App target，一个测试 target。目录表示职责，不创建独立 framework。

```text
CalMon.xcodeproj/
CalMon/
  App/
    CalMonApp.swift
    MenuBarController.swift
    Preferences.swift
    UIStyle.swift
  Calendar/
    CalendarModel.swift
    HolidayProvider.swift
    CalendarView.swift
  Monitoring/
    SystemMonitor.swift
    AppMemoryReader.swift
    MonitoringView.swift
  Settings/
    SettingsView.swift
  Resources/
    Assets.xcassets/AppIcon.appiconset/
    SolarTerms/YYYY.json
    PrivacyInfo.xcprivacy
    CalMon.entitlements
CalMonTests/
  MonitoringTests.swift
  CalendarTests.swift
  LifecycleTests.swift
```

- CalMonApp 负责启动/退出。使用 accessory/LSUIElement 行为，不创建多余主窗口。
- MenuBarController 持有两个 NSStatusItem、各自弹窗和共享右击菜单，路由不落入业务模型。
- SystemMonitor 管理一次调度、整机统计、设备/容量信息及当前快照。
- AppMemoryReader 管理 PID 枚举、footprint、应用归属与图标；它不拥有独立定时器。
- CalendarModel 管理可见月、选中日、日期网格和详情；HolidayProvider 管理 EventKit、节气静态表、来源识别、去重和权限。
- 两个业务模块不互相引用，不共享一个全局可观察对象；监控变化不触发月历重建。
- Preferences 仅为设置和系统登录项适配；UIStyle 仅为公共视觉常量。
- 允许在职责不变前提下小幅合并/拆分文件；禁止通用服务总线、仓库层、依赖注入框架或过度协议化。
- SwiftUI 状态在主执行器发布，耗时系统查询离开主执行器；查询串行不重入，任务完成时核对当前有效性。
- 不在 View.body 创建格式器、枚举进程、读取磁盘或申请权限。
- 首版按本地 macOS 应用交付，不以 App Store 上架为目标。不使用管理员权限/helper。若启用 sandbox，必须验证进程采样与 EventKit 权限可用，不能在限制下悄悄退化为假零。
- 所用 required-reason API 必须按 Apple 当前规范配置 PrivacyInfo.xcprivacy；选择与实际功能一致的原因，不编造原因代码。
- AppIcon 复制正式 appiconset，源包保持不变；图标数字是静态装饰，不做动态图标。
- Xcode 自动生成的配置、资源和必要签名项不受“少 Swift 文件”限制。

## 8. 调度与资源

- CPU/MEM：监控启用时一个 3 秒调度源，允许 0.3 秒调度容差；实际计算使用真实样本时间/计数，不依赖精确触发时刻。
- 应用列表：监控弹窗打开立即读取，此后复用上述 3 秒调度；关闭/禁用取消后续任务并丢弃过期结果。
- 磁盘：监控弹窗打开读取一次，可见期间每 30 秒读取，复用主调度时钟；关闭后不读。
- 日历：按打开、切月、数据变化通知更新，不随监控刷新。
- 系统休眠不阻止、不补跑；唤醒重建 CPU 基线并更新日期。
- 查询慢于周期时跳过重叠采样，不能堆积后台任务。
- 无自定义常驻动画、高精度忙等、外部命令、生产采样日志或常驻网络连接。

## 9. 实施交付

实施顺序：工具链与 API 可读性验证 → 监控公式校准及日期计算 → 模块与菜单栏 → 两个弹窗 → 设置/登录项/权限 → Release 验收。

最终交付须满足 ACCEPTANCE.md。公开 API 的可读范围、内存字段映射和节日覆盖范围必须提供证据；不能以规格完整代替实现完整。
