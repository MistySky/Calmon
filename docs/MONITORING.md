# 监控数据与调度规范

## 1. 基本要求

所有显示值来自公开系统 API 的有效样本。菜单栏、圆环、容量文字共用快照；禁止在各视图重复读取或采用不同公式。产品不记录历史，只保留当前快照及计算 CPU 所需的前一份计数。

精度分三层：原始系统计数/字节 → 未取整的业务值 → 展示字符串。准确性验证比较前两层，不能只比较整数显示。

## 2. CPU

- 使用 Mach host_statistics / HOST_CPU_LOAD_INFO，核实当前 SDK 类型和计数器位宽。
- 两次有效采样之间计算：CPU = 100 ×（总 ticks 增量 − idle ticks 增量）/ 总 ticks 增量。
- 总增量包括全部 CPU 状态，所有逻辑核心归一化到 0–100%。与活动监视器底部 System + User（或 100 − Idle）比较，不与单进程百分比或进程百分比之和比较。
- 显示整数，四舍五入；不叠加移动平均。
- 首次/重新开启/唤醒读取基线，下一份有效样本才显示 CPU；此前为 --%。
- 总增量为零、调用失败、无法解释的计数回退或重置则无效并重建基线。
- 已验证的计数器回绕按位宽计算，不能将所有负差值强制归零。
- 系统回调时刻不保证精确 3 秒；使用实际计数区间计算，不按固定墙钟间隔伪造增量。

## 3. 整机内存

### 3.1 目标语义

- MEM = 已使用内存 / 物理内存 × 100%。
- 已使用内存对齐活动监视器 Memory Used：`physical − (free_count − speculative_count)×pageSize − external_page_count×pageSize`。
- 不展示内存组成（应用/联动/压缩/剩余）；不因删 UI 改变上述已用公式，也不撤掉异常样本保护。
- 文件缓存不能全部当成使用中的 App Memory；swap 不加入物理使用量。
- 压缩部分按占用的物理空间处理，不将压缩前逻辑大小与压缩器占用重复累计。
- 不采用总内存减空闲页、进程 RSS 合计或逐应用合计替代整机 Memory Used。

### 3.2 读取和证明责任

读取来源为 host_statistics64 / HOST_VM_INFO64、系统页大小与 ProcessInfo.physicalMemory。不能硬编码 4096/16384 页大小，不能先转成 GB 再计算比例。

Apple 用户文档未给出 Memory Used 到全部内核字段的完整算法保证，因此实施必须在提交时提供：

1. 最终使用的每个字段、单位、字节换算和完整公式。
2. 为什么排除可回收缓存、如何处理压缩/联动/应用内存。
3. 空闲、缓存增长/释放、压缩发生等场景的活动监视器对照。
4. 支持的 macOS build 与差异分析。

这些是实现验证任务，不是可省略的文档空位。未经验证的通用网络公式不能作为合格实现。若公开字段无法满足精度要求，应明确报告无法通过准确性验收，不能悄悄改成“近似”而宣称完成。

### 3.3 内部一致性

- 原始字节级：已使用不超过物理内存。
- 矛盾样本判为无效并显示 `--`：physical=0、free 超物理量、speculative 超 free、internal 超物理量、purgeable 超 internal、分项（app/wired/compressed）超物理量、分项之和超物理量（用减法界限检查防溢出）、effectiveFree+external 超物理量、或分项合计超公式 used。不截断字段，不通过抬高 used 配平。
- 字段并非同瞬间或含统计残差时，先调查语义；不向某项偷偷塞入差额以凑整。
- 无效快照不得更新为假零，也不得以持续显示上一次数值冒充实时有效。
- 同一快照更新菜单栏、内存圆环与容量文字。显示舍入造成的最后一位差异可解释，不能出现明显相互矛盾。

## 4. 应用内存

### 4.1 范围与读取

- 列表单位为正在运行的应用，不是所有系统进程。至少覆盖当前用户可识别的图形应用及可证明归属的 helper。
- 使用 NSWorkspace 获取应用身份/图标，公开 libproc 枚举必要进程及采集资源。
- 优先核实 proc_pid_rusage 的 ri_phys_footprint 与活动监视器所选内存列的对应关系；不得把 ri_resident_size、虚拟内存或地址空间大小冒充 footprint。
- 不能假定能够读取所有 PID；进程退出、权限拒绝、PID 复用均须处理。ID 需结合启动身份，不仅以 PID 长期缓存。
- 不请求管理员权限、不使用 task_for_pid 绕过系统保护、不引入特权 helper。
- 无法读取的应用行显示“不可读取”或 --；部分进程可读时显示“部分数据”，不能声称是完整总量。

### 4.2 应用归属与汇总

- 使用 bundle 身份、进程可执行路径和可验证的进程关系确定归属，不仅靠名称 contains 或所有同签名进程合并。
- 避免将多个独立应用、同厂商软件或系统共享服务归到一个应用。
- 每个 PID 最多计入一个应用；helper 只在归属明确时合并。
- 行数值定义为该应用归属进程组的已读 footprint 合计；详情提示/辅助说明可列出进程数量与“部分数据”状态。
- 合计是应用进程组口径，不宣称为物理页去重后的整机消耗；不能把全表合计等同于 Memory Used。
- 与活动监视器验证时比较相同 PID 集合和对应字段，不拿 Chrome 主进程一行与整个 Chrome 组比较。
- 无法确定归属的进程不猜测归并，验证报告列明覆盖边界。

### 4.3 UI 与生命周期

- 面板打开立即采样，之后每 3 秒刷新；关闭停止。
- 每行占用条 = 行内存 / 物理内存，文字保留 MB/GB；不能按当页最大值缩放。
- 降序排序，平局按名称和稳定 ID；用户操作列表时冻结顺序，不冻结数值。排序恢复不能改变焦点指向的应用。
- 默认八行，“查看更多…”展示完整已识别应用列表；无数据与权限失败有独立状态。
- 搜索按聚合应用显示名（`AppUsage.name`）做大小写不敏感连续子串过滤，范围是完整已识别应用快照（不限前八行）；不匹配拼音、bundle ID、进程名或 PID。搜索时不改变聚合/占用/排序/刷新，隐藏“查看更多/收起”，无结果显示“未找到匹配应用”；清空查询恢复原展开状态，弹窗关闭清空查询。详见 [MONITORING_APP_SEARCH.md](MONITORING_APP_SEARCH.md)。
- 查询中退出的进程跳过并更新状态，不导致整轮崩溃。新应用下个有效周期出现。
- 图标只在身份变化时读取，缓存有界；不能每 3 秒重新解码全量大图标。

## 5. 启动磁盘容量

- 展示启动磁盘数据卷的总容量、可用容量，以及计算的已用容量和百分比。
- 使用同一卷的 Foundation URL 资源容量 API；记录实际查询 URL、卷标识、字段和字节单位。
- 在 APFS 卷组上选择用户数据实际所在的启动数据卷，不能将只读系统卷、多个共享卷容量相加。
- 基础口径：可用 = volumeAvailableCapacity；已用 = volumeTotalCapacity − 可用；占比 = 已用 / 总量。
- 不把 availableCapacityForImportantUsage 或可回收空间与基础可用混用；不声称其数值等于 Finder/系统设置的所有存储分类。
- 只读取容量，不遍历文件、不按应用计算安装体积、不统计网络卷或外置磁盘、不读 I/O 速率。
- 打开面板读取，可见时每 30 秒读取；关闭不读取。不因 CPU 3 秒更新而每个视图重读磁盘。
- 容量异常（总量为零、可用大于总量、API 失败）显示 --，不强行截断后呈现成功。
- 根据实际 API 使用配置 PrivacyInfo.xcprivacy 的必要原因声明。

## 6. 单位与显示

- 全部业务计算使用字节。
- 内存（整机容量、占用圆环、应用内存）使用二进制单位（1 GB = 1024³ bytes，1 MB = 1024² bytes），标签写作 GB/MB，与活动监视器一致；本机 32 GiB 显示为 “32 GB”。
- 磁盘容量沿用 Finder 的十进制单位（1 GB = 1,000,000,000 bytes）；对照时先归一单位。
- 应用 < 1 GB 显示整数 MB；≥ 1 GB 显示两位小数 GB；非零但小于 1 MB 显示 <1 MB，不伪装零。
- 整机内存与磁盘容量均最多一位小数 GB；可省略无意义的 .0。
- CPU/MEM/磁盘百分比整数，四舍五入；圆环/条形长度使用未取整数值。
- 无效百分比 --%，无效容量 --。错误不能显示旧值为有效状态。
- 测试核对 256/512 GB = 50%，21.4/32 GB 四舍五入 = 67%。示例只用于算术一致性，不是生产假数据。

## 7. 状态、刷新和并发

| 状态 | 整机 CPU/MEM | 应用列表 | 磁盘 |
|---|---|---|---|
| 监控禁用 | 停止 | 停止 | 停止 |
| 启用、面板关闭 | 3 秒 | 停止 | 停止 |
| 面板打开 | 3 秒 | 立即 + 3 秒 | 立即 + 30 秒 |
| 休眠 | 不保活 | 停止 | 停止 |
| 唤醒 | 重建 CPU 基线 | 可见才恢复 | 可见才读取 |

- 使用一个 3 秒调度源，容差 0.3 秒。磁盘截止时刻由单调时钟判断，重用该源。
- 同类采样串行；未完成时跳过下一次，不叠加任务。每次结果附采样时间与有效性。
- 关闭弹窗/禁用/切换期间取消任务或通过 generation 校验丢弃过期结果。
- 采集不阻塞 UI；在主执行器一次发布对应快照，不让部分组件短暂拿到新旧混合数据。
- 生产不保存采样序列；验收临时记录由开发者主动执行，不随 App 自动运行。
