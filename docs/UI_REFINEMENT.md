## 0. 优先级与范围

- 用户明确要求：菜单栏更紧凑、字体更小；彻底移除内存组成；应用按软件聚合；设置去掉刷新说明，周起始日改横向单选；去掉节日来源选择，改系统日历授权；统一两类弹窗材质及箭头；整理月历提示点和详情，参考图七。
- 本文给出的具体尺寸、统一采用监控弹窗材质、日历详情排布和自动识别来源策略，是为实施选定的设计方案，不是用户提供的实测数值。按此方案先实现，再以同机截图验收；不得声称已精确测量 Mole/MacCalendar 的字号。
- 本文覆盖旧 SPEC/UI_SPEC/MONITORING/ACCEPTANCE 中与本轮直接冲突的要求：内存组成展示及其专属模型、用户手选节日来源、旧字号/间距、月历详情布局。旧报告和截图是历史证据，不得据其恢复已删除功能。
- 其余功能和准确性要求保留；不借本轮增加功能、改变正常样本 CPU/MEM 公式、刷新周期、磁盘口径或重构整个工程。
- 仍为 Swift + SwiftUI/AppKit、macOS 27、公开 API、无第三方依赖、无数据库、无监控历史。当前文件与模块边界保持轻量。
- 内存仍以二进制 GB/MB 显示，磁盘仍以十进制 GB 显示；无效数据不伪造零、不配平；保留已修复的采样生命周期、并发失效和权限复用行为。
- 开发验证沿用隔离测试宿主。不得自动安装、覆盖或启动正常 App；最终用户通过 DMG 手动安装、启动。

## 1. 整体与菜单栏

### 1.1 两个独立入口，更紧凑

- CPU/MEM 与日期继续是两个独立菜单栏项目，独立命中、左击展开各自面板、右击共享“偏好设置… / 退出”。同时最多一个弹窗。
- 减少图一圈出的监控与日期之间的视觉空白。优先消除 App 自带画布空白和重复内边距，保留系统管理的项目间距；不合并成一个按钮、不用负坐标或透明占位项目模拟间距。
- CPU/MEM 每侧内边距从 6 pt 调整为 3 pt；标签到数值 3 pt。日期每侧内边距同为 3 pt。画布只容纳字形和这些边距。
- CPU/MEM 保持两行，每行 9 pt、合计约 18 pt；预留 100% 和 --% 的自然字宽，不预留多余空列。数值采用等宽数字，变化时不跳宽。
- 日期格式保持“9月15日 周二”，星期仍可关闭。日期自然宽度，不额外增加固定空白。
- 实机在相同显示倍率和菜单栏高度下，与用户本机 Mole、MacCalendar 并排查看；目标是相近的紧凑感，不能仅把 Retina 截图像素当 pt。

### 1.2 统一字号基线

全部为逻辑 pt、系统字体。共用 UIStyle 管理，不在每页单独放大或缩小。

| 角色 | 本轮值 | 约束 |
|---|---:|---|
| 菜单栏日期 | 12 regular | 原 14 medium 偏大，优先缩小此项 |
| 菜单栏 CPU/MEM | 8.5 medium | 等宽数字；实机确认两行不裁切 |
| 月标题/面板标题 | 14 medium | 不用大号粗体 |
| 正文、应用名/数值、设置标签 | 12 regular | 同角色统一 |
| 分组标题 | 12 medium | 不额外加重 |
| 次级说明/详情辅助文字 | 11 regular | 不为挤进单行继续缩小 |
| 星期标题 | 11 medium | 用“周一…周日”，不要仅“一…日” |
| 月历日期数字 | 14 regular | 今天 medium |
| 格子农历/节日 | 10.5 regular | 保持可读，长文截断并提供完整提示 |
| 班/休角标 | 9 medium | 与数字不重叠 |
| 圆环百分比 | 18 medium | 三个概况卡统一 |

原生菜单、窗口标题及原生控件内部字形由系统管理，不自绘这些组件。若系统控件字号无法精确匹配，使用统一的原生 controlSize 并在截图中说明。

### 1.3 毛玻璃与箭头：统一以监控弹窗为基准

**选定当前监控弹窗的中性半透明外壳作为两者共同基准。月历只参考图七的内容结构，不照搬它的另一套外壳。**

- 日历、监控使用同一原生弹窗外壳配置、外观继承、阴影和透明背景策略；内容卡片使用同一组低对比中性背景。
- 不给月历单独叠蓝白底色、渐变、额外模糊、边框或第二层阴影；不固定 blur 半径，不为模仿截图自绘玻璃。
- 两者的顶部锚点箭头均由同类系统外壳产生，并锚定实际被点击的状态栏按钮。检查箭头与面板衔接是否出现色差、横线、尖角或裁切。
- 图六的蓝色整面板框需要排查焦点呈现，不能把焦点框当成玻璃描边保留。调整焦点落点及绘制范围，保留键盘焦点可见性和 Esc 关闭能力。
- 系统减弱透明度时，两者同时遵循系统；明暗和增加对比度同样同步。内容不同、背景壁纸不同会影响视觉，但不允许人为配置两套材质。
- 外边距统一 16 pt，卡片内边距 12 pt、圆角 10 pt；不改系统弹窗外壳圆角。两者内容宽度继续分别为日历 360 pt、监控 400 pt，不强行等宽。

## 2. 日历

### 2.1 日期网格：参考图七的紧凑结构

- 保留月标题、前后月导航、周起始设置、农历、节气、节日、今天/选中状态、邻月日期、班/休。
- 月标题居中，左右切月图标同字重、同尺寸；视觉图标约 11–12 pt，点击区域保留 28×28 pt，不能为了缩小图标缩成难点中的按钮。
- 日期行从 52 pt 收紧到 48 pt；七列等宽，4–6 行随月份变化。数字与第二行文字作为一个紧凑组，行间 1 pt。
- 今天与选中圆直径 34 pt，包含数字及第二行文字，参考图七；今天圆内两行白色，非今天选中为浅红圆。点和班/休角标在圆外，不能遮住字形。
- 第二行优先级保持：实际节日名称 > 节气 > 农历日期。月初的农历初一可显示月名，以图七习惯呈现。
- **休假安排名称不等于当天节日。** 例如中秋假期三天不都显示“中秋节”；国庆补班日不能显示为“国庆节”当天。假期/补班标记照常显示，详情可说明“国庆假期补班”；网格节日名来自实际节日日期，不能把年度安排的 name 直接铺满休假区间。
- 班/休角标距格子上、右边各 2 pt，12×12 pt；已知邻月班/休也显示，随邻月淡化，不因为不属于当前月而隐藏。
- 不从周末推断休/班；官方年度安排来源及覆盖不足状态保留。

### 2.2 提示点：独立位置、不压文字

- 绿色提示点直径 4 pt，位于日期单元格底部居中；为点预留独立 6 pt 布局区，文字与点至少间隔 2 pt。
- 不能把点直接 overlay 到第二行文字基线上。日期内容组应为点预留高度，避免只改变 padding 后仍重叠。
- 有可展开的节日/节气/班休说明时显示一个点；多个信息仍只显示一个，点击后在详情展开。普通日期没有无意义的点。
- 今天、选中、邻月、长名称、有班/休等组合都要核验点的位置。

### 2.3 下方详情：一个日期摘要区 + 一个紧凑列表

参考图七的信息组织，不保留图六逐行堆积的“日期 / 农历 / 今天 / 当天无节日 / 来源未连接 / 今天按钮”。

1. 网格后用一条系统细分隔线，前后各 12 pt。
2. 摘要区左侧公历日期与 ISO 周数，右侧农历年/生肖/月日。12 pt 正文、11 pt 辅助信息；星期仍在摘要或辅助说明中可见。
3. 在 360 pt 面板内优先两列对齐；空间不够时摘要最多两行自然换行，不缩小字体、不截断农历、不强塞一行。关闭农历后右侧区域收起。
4. 摘要下方间隔 8 pt，用紧凑浅色列表呈现相对日期和当天节日。今天只呈现一条“今天”；过去/未来分别呈现“距今天已过 N 天 / 距今天还有 N 天”。
5. 事件行参考图七：左侧窄列“全天”，右侧浅色圆角内容块、3 pt 绿色竖线；正文 12 pt。这里的“全天”仅表示日期信息/节日，不引入个人日程功能。相对日期行不强制加“全天”标签。
6. 节日事件与休息/补班事件分别展示：“中秋节”和“中秋节（休）”可各占一张卡，休息/补班事件保留对应短标签。用户已确认这种展示正常，不得跨事件类型合并；只去除同类同义的重复条目。
7. 普通日期只保留相对日期行，不再额外占一行写“当天无节日”。数据覆盖不足或读取失败仍用一条紧凑说明区分，不能伪装为正常无节日。
8. 常态月历不显示“系统节日来源未连接”或引导授权的大块内容；权限管理集中在设置。出现权限问题时月历最多一条次级状态，如“系统节日暂不可用”，不重复申请权限。
9. “回到今天”仍保留：选中非今天或当前月不是本月时显示在月标题附近；已在今天时不占底部一行放按钮。底部没有设置、退出按钮。

详情过多时局部滚动，小屏时整个内容允许滚动；没有水平滚动、被裁切的底部或固定大块空白。

## 3. 监控

### 3.1 完整移除内存组成功能

- 删除“内存组成”标题、组成条、应用/联动/已压缩/其他/剩余的图例、数值及该卡片占用的全部空间。
- 删除仅服务该展示的 view、常量、颜色、公开展示字段、帮助文字与测试断言；不改成折叠项、开关、tooltip 或其他页面继续保留。
- **保留整机 MEM 计算必需的底层字段与合法性检查。** 公共快照中不再暴露只用于组成展示的字段；校准/校验仍需要的中间量可留在采样模块内部。不能因删 UI 把已用内存改成错误的总量减 free，或撤掉异常样本保护。
- 组成图专属测试删除；CPU/MEM 正确性、无效样本、原始记录字节回归及生命周期测试继续保留并适配。

### 3.2 其余概况保持

顺序为：设备概况 → CPU/内存/磁盘三个当前值卡片 → 应用内存列表。

- 三个概况卡片、圆环、颜色、含义、容量文字保持；只遵循本轮统一字体，不重新设计卡片内容。
- 删除组成卡后自然缩短弹窗，不留空容器或保留原高度。
- CPU/MEM 3 秒刷新不变；应用列表仅面板可见时采样；磁盘 30 秒复用同一调度源。无历史趋势、安装体积或磁盘读写功能。

### 3.3 按“软件”聚合，不把 helper 当软件单列

- 图二的“飞书”和属于它的“Lark Helper”应归为一行“飞书”，使用主 App 的名称和图标；数值为本轮该软件全部已确认归属进程的 footprint 合计。
- 如果图二 831 MB 与 788 MB 确为同轮、不重叠的两个已读集合，应相加后按现有单位规则显示；不可只保留其中一行，也不能把截图数值写死。
- Chrome、飞书等同理：Renderer、GPU helper、子 bundle 等在归属可证时合入主软件。主 App 优先于嵌套 helper，不再单纯用“最深 bundle 匹配”产生多行。
- 身份依据使用安装包层级、bundle 身份、可执行路径及可证明的进程关系；处理 PID 复用/退出。每个 PID 最多计一次；同名、同厂商或名称中含 Helper 不能单独作为合并依据。
- ChatGPT 与 ChatGPT Classic、同厂商不同产品、不同安装实例不能仅按名称/签名归并。必要时以规范化主 bundle 路径区分实例，保持行 ID 稳定。
- 无法证明归属的辅助进程不能猜测；尽量展示为其可识别独立应用，并在验证材料说明覆盖边界。不能把不确定总量标记为完整软件占用。
- 部分已确认进程不可读时，主软件行显示“部分数据”；全部不可读显示 `--`。某个 helper 退出不能使整个列表崩溃。
- 保留按内存降序、前八个软件、“查看更多…/收起”、悬停/交互时冻结排序、物理内存作为条形分母。聚合后先排序，再取前八行。
- 不为了聚合引入新定时器、shell、管理员 helper 或第三方依赖。保留有界图标缓存与关闭后的清理。

### 4.2 系统日历权限行

行标题为“系统日历权限”，右侧按系统状态显示状态/动作，不用布尔开关伪装系统权限。

| 系统状态 | 显示 | 点击行为 |
|---|---|---|
| 尚未决定 | “获取权限”按钮 | 用户点击后请求系统日历读取所需权限 |
| 请求中 | “正在请求…” | 暂时禁用重复触发 |
| 已授权 | “已授权” | 不再次请求；需要时提供小型系统设置入口 |
| 拒绝/撤销 | “未授权” + “打开系统设置” | 前往设置，不反复弹系统请求 |
| 系统限制 | “访问受限” | 简短说明；不承诺用户一定能够解除 |

- 系统是授权真相来源，不在本地自行记“已授权”代替检查；授权与事件内容可用是两种状态。
- 授权有效时启动、切月、开关模块、手动覆盖安装新版都复用，不重新发起请求。签名和 Bundle ID 保持稳定，DMG 双版本授权继承实际验证要求不变。
- 仍只读取节日，不编辑日历、不引入个人日程；授权不是读取所有个人事件的许可范围。

### 4.3 去掉来源选择后的内容策略

- （已被 UI_REVIEW_FOLLOWUP 覆盖）用户不再手选来源。基础公历/农历内部显示；节日/班休仅来自系统日历，不内置。
- 获得权限后，通过公开 API 自动发现系统中可明确识别的中国节日日历，并仅查询这些来源的可见日期区间。候选来源和选用规则需要在实施报告记录，不能只看见“日历可读”就读取全部事件。
- 只读/订阅属性不等于“节日日历”；名称关键字也不能单独保证身份。不得默认读第一个日历、默认个人日历或合并全部事件；不得使用私有 API 去读 Calendar 数据库。
- （已被 UI_REVIEW_FOLLOWUP 覆盖）没有可用节日订阅或无法可靠判定时，显示普通公历/农历月历；权限行按真实授权显示，不伪造成败、不恢复来源 Picker。
- 如果公开元数据确实无法支持可靠自动识别，先提交具体限制和候选证据，保留内置节日能力；不要声称“获取权限就一定能获得系统中国节日”。此项是技术证明责任，不是凭猜测扩大读取范围。
- 旧版本保存的来源偏好不能继续驱动隐藏的任意日历读取；迁移到新策略，保留有效系统授权。来源变化按通知刷新，模块关闭时停止无关查询。

## 5. 验收约束

### 5.1 本轮必验

- 菜单栏 0/9/99/100/-- 不跳宽、无裁切；两个项目独立命中，圈出的空白明显减少。附同机 Mole/MacCalendar 比较图，不声称像素完全复制。
- 两个弹窗在同一壁纸、系统外观、倍率下分别截图，外壳材质/阴影/箭头一致；浅色、深色、减少透明度、增加对比度均检查。
- 监控不存在任何内存组成 UI、空位或入口；三个概况卡和其数值正确性没有回归。
- 飞书至少覆盖主进程和多个 helper；提供主 bundle、PID 集合、原始 footprint、合计、聚合前后行数。Chrome 同样验证；独立 App 不误合并、PID 不重复。
- 月历普通日、今天、选中非今天、邻月、节日/节气、班/休、长名称和多条详情均检查；点不压字，邻月班/休不消失，假期名称不冒充实际节日日期。
- 底部详情不重复堆文字，常态没有“来源未连接”长提示；回到今天、键盘和辅助功能保留。
- 设置去掉刷新说明；周起始日为原生横向单选；权限行覆盖上述状态，已授权不重复请求。
- 保留隔离回归测试、Debug/Release 构建；与统计有关的修改补充准确性、完整枚举后的性能检查。旧版性能数字不能直接冒充本轮结果。
- 把权限自动识别的可行性、降级情况和实机结果写清。DMG/签名未完成时明确标未执行，不提前宣称覆盖安装可继承授权。

### 5.2 交付内容
